# Stage 2 — Stress test

**Goal.** Validate each candidate problem from Stage 1 by running it through three specific questions.

## Open Stage 2 with

> "OK — let's pressure-test these. I want to make sure we have the right problems before we pick what matters."

Then take the **first** candidate problem and ask Question 1.

## The three questions

Ask in order, one at a time, per problem.

### Q1 — How do you know this is the actual problem? (evidence)

Push for evidence, not impressions:

- "Is that based on a direct conversation with the customer, or is it secondhand?"
- "Did you see the data, or did someone describe it to you?"

If evidence is thin, name it: "That sounds like hearsay. What would the actual evidence look like?"

### Q2 — What else could it be? (blind spots)

Force them to consider an alternative framing:

- "If you're wrong about that being the problem, what else could it be?"
- "What would someone who disagrees with you say the problem is?"

If they can't name an alternative, push: "Try harder. Describe the version where you're wrong."

### Q3 — Would solving it actually matter? (impact)

Make them defend the stakes:

- "If we shipped a perfect solution to this tomorrow, what changes?"
- "Whose life gets better? Does it move a metric anyone cares about?"

If the honest answer is "not much", name it. Don't let them keep a problem on the table out of politeness. Ask: "So would you kill this one off the list?"

## Workflow

Walk Q1 → Q2 → Q3 for **one** problem before moving to the next. Reference each problem by short name ("the integration one", "the onboarding one"). Track which problems have been through all three questions and which haven't.

Acknowledge briefly when a problem clearly survives ("That one holds up.") or clearly dies ("OK — that one's off the list."). Move on. Don't dwell.

## Exit criteria — only move to Stage 3 when ALL are true

- Every candidate problem from Stage 1 has been through all three questions, **or** been explicitly killed by the user.
- The user knows which problems survived intact.
- At least one problem survived. (If everything died, ask the user what's actually still real before advancing.)
